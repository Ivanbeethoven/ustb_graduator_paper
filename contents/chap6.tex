
\chapter{案例分析}\label{chap:case}
在上一章总体实验基础上，本章选取 7 个典型 CVE 案例，进一步考察本文方法在真实云原生权限提升漏洞场景中的表现。每个案例包括\textbf{漏洞复现}、\textbf{策略生成}与\textbf{三维质量验证}三个阶段：在可控环境中重现攻击路径并确认风险；基于本文方法生成\textbf{监控策略}与\textbf{防护策略}候选；再从有效性 $E$、无干扰性 $I$ 与可部署性 $D$ 三个维度评估策略是否能够阻断攻击且具备工程可行性。


\section{案例分析实验设计}

\subsection{CVE 案例选择标准}

为保证案例具有代表性且可复现，本文按以下标准筛选 CVE：

\noindent\hangindent=2em\hangafter=1 \textbf{风险等级与影响范围}：优先选择 CVSS 评分 $\geq 5.0$ 且在 Kubernetes 生态中影响较广的漏洞，如核心组件漏洞或高使用率第三方应用漏洞。

\noindent\hangindent=2em\hangafter=1 \textbf{成因类型覆盖}：确保所选案例覆盖本文两级成因分类框架中的主要类别，包括配置缺陷、安全逻辑缺陷、敏感信息泄露与代码注入等，以检验方法的适用范围。

\noindent\hangindent=2em\hangafter=1 \textbf{可复现性}：漏洞具备公开的攻击 PoC 或较完整的技术细节，可在隔离环境中安全复现；同时受影响版本与修复版本明确，便于对比验证。

\noindent\hangindent=2em\hangafter=1 \textbf{防控价值}：漏洞场景具有明确的临时防控需求，如补丁尚未发布、业务无法立即升级或需要多层防御，因此更适合评估智能生成策略的实际价值。

\noindent\hangindent=2em\hangafter=1 \textbf{漏洞复现流程}。对每个 CVE，本文按以下步骤进行复现：
\begin{enumerate}
    \item \textbf{基线环境准备}：部署受影响版本的目标组件，并创建模拟的业务负载与用户身份（如低权限 ServiceAccount）；
    \item \textbf{攻击执行}：根据公开 PoC 或技术分析，模拟攻击者执行权限提升攻击，记录攻击步骤与观测到的异常行为；
    \item \textbf{影响确认}：验证攻击是否成功实现权限提升（如获取集群管理员权限、访问受限资源、执行特权操作等）；
\end{enumerate}

\noindent\hangindent=2em\hangafter=1 \textbf{策略生成与验证}。漏洞复现成功后，使用本文方法生成安全策略并进行三维评价：
\begin{enumerate}
    \item \textbf{安全上下文构建（检索增强（RAG））}：将 CVE 公告、受影响组件文档、攻击日志与社区讨论输入向量知识库，检索与漏洞相关的证据；
    \item \textbf{策略生成（思维链推理（CoT）与反馈优化（Feedback））}：基于检索增强上下文与漏洞分析结果，生成候选策略并进行评审反馈优化；
    \item \textbf{策略部署与复测}：在测试集群中部署生成的安全策略（如 NetworkPolicy、RBAC 规则、Gatekeeper 策略等），重新执行攻击以验证策略是否有效阻断；
    \item \textbf{三维质量评价}：
    \begin{itemize}
        \item \textbf{有效性（E）}：策略能否成功阻断原攻击路径，是否存在绕过可能；
        \item \textbf{无干扰性（I）}：策略对正常业务流量的影响，如误报率、性能开销与运维复杂度；
        \item \textbf{可部署性（D）}：策略配置的完整性与可执行性，是否包含清晰的验证与回滚方案。
    \end{itemize}
\end{enumerate}

\section{小结}
本章案例验证表明，7 个覆盖不同成因类型的典型 CVE 在隔离集群中均可完成漏洞复现与策略部署验证。如表~\ref{tab:case-summary-eid}所示，生成的监控策略与防护策略在有效性维度上均能阻断或显著缓解攻击路径；在无干扰性维度上，多数策略对业务影响可控，但仍需在预生产环境验证；在可部署性维度上，策略主要依赖 Kubernetes 原生能力与成熟准入控制组件，具备进一步模板化推广的条件。
