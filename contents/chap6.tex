
\chapter{案例分析}\label{chap:case}
本章选取 7 个典型 CVE 案例，考察 KPEDefense 针对真实云原生权限提升漏洞进行安全防控的有效性。每个案例包括\textbf{漏洞复现}、\textbf{策略生成}与\textbf{部署验证}三个阶段。


\section{案例分析实验设计}

\subsection{CVE 案例选择}

为保证案例具有代表性且可复现，研究按以下准则选择云原生权限提升CVE作为案例：

\begin{itemize}
    \item \textbf{风险等级与影响范围}：CVSS 评分 $\geq 5.0$，在 Kubernetes 生态中影响较广，如核心组件或高使用率第三方应用漏洞。
    \item \textbf{成因类型覆盖}：所选案例覆盖两级成因分类框架的主要类别，包括配置缺陷、安全逻辑缺陷、敏感信息泄露与代码注入等，验证方法的适用范围。
    \item \textbf{可复现性}：具备公开 PoC 或完整技术细节，可在隔离环境中安全复现；受影响版本与修复版本明确，便于对比验证。
\end{itemize}

\textbf{漏洞案例分析流程}。对每个权限提升CVE，依据如下步骤进行分析：
\begin{enumerate}
    \item \textbf{漏洞复现}：为有效进行安全策略验证，需根据CVE描述进行漏洞复现。部署受影响版本的目标组件，创建模拟业务负载与低权限身份；根据公开 PoC 或技术分析模拟权限提升攻击，记录攻击步骤与异常行为；验证是否成功实现权限提升。
    \item \textbf{安全策略生成}：基于 KPEDefense 系统，使用至少三个大模型生成候选安全策略，并通过静态评估从有效性 $E$（阻断攻击路径）、无干扰性 $I$（对业务的影响）、可部署性 $D$（配置完整性与可执行性）三个维度综合评估，筛选出一个最佳的安全策略集合。
    \item \textbf{策略验证}：部署生成的安全策略，并根据漏洞复现执行攻击测试，验证策略能否对漏洞进行有效监控和防护，并根据三维质量评价体系分析结果。
\end{enumerate}

\section{小结}
7 个覆盖不同成因类型的典型 CVE 均在隔离集群中完成了漏洞复现与策略部署验证。如表~\ref{tab:case-summary-eid}所示，生成策略在有效性维度上均能阻断或显著缓解攻击路径；在无干扰性维度上，多数策略对业务影响可控，但仍需在预生产环境验证；在可部署性维度上，策略主要依赖 Kubernetes 原生能力与成熟准入控制组件，具备模板化推广的条件。
