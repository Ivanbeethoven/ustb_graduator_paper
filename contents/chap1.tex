\section{背景与意义}
容器技术借助内核级资源隔离与标准化镜像分发，改变了微服务应用的构建与交付方式\cite{wuyiwen2023docker}。$\mathrm{Kubernetes}$ 作为主流容器编排平台，为复杂业务的部署与弹性扩展提供了基础支撑\cite{kubernetes2024,alibaba2024}。云原生计算基金会 $\mathrm{CNCF}$ 2025年度调查报告\cite{lawson2026cncf}显示，生产企业 Kubernetes 采用率已达98\%，66\% 的组织已在 Kubernetes 上运行AI工作负载。随着业务规模增长，$\mathrm{Kubernetes}$ 集群往往需要集成大量第三方开源组件，这些组件通过基于角色的访问控制（$\mathrm{RBAC}$）机制\cite{ferraiolo1995role}获取集群资源访问权限。然而，第三方应用在增强平台能力的同时也带来了安全隐患——多租户场景下，过度权限配置\cite{yang2023take}、权限管理缺陷、敏感信息泄露\cite{kubeguard_icws2025}、网络隔离缺失等因素都可能引发权限提升风险。此类漏洞威胁性高、修复周期不确定，且成因与利用路径各异，给企业安全防控带来持续压力。

围绕云原生安全治理，学术界和工业界已积累了一定的工具链与方法体系。静态层面，针对镜像依赖、$\mathrm{Kubernetes}$ 清单及 $\mathrm{IaC}$ 模板的漏洞与误配置扫描被广泛用于风险前置发现\cite{shamim2025prescription,k8smanifests2023}；运行时层面，基于系统调用或 $\mathrm{eBPF}$ 事件的观测审计能够辅助异常检测与攻击取证\cite{falco2025}；防护层面，$\mathrm{OPA/Gatekeeper}$\cite{opa2025}、$\mathrm{Kyverno}$\cite{kyverno2025} 等准入控制器可拦截不合规资源进入集群，网络策略则通过最小连通约束抑制横向移动\cite{Minna_2021,Budigiri_2021}。然而上述手段在面对权限提升漏洞时仍有如下不足：

\noindent\hangindent=1em\hangafter=1 (1) \textbf{处置精准度不足}。多数方法依赖通用静态规则或单一方向检测，无法结合特定 $\mathrm{CVE}$ 的利用前置条件与攻击链路给出有针对性的处置方案\cite{shamim2025prescription,shamim2025dastk8s}。

\noindent\hangindent=1em\hangafter=1 (2) \textbf{防控策略难以复用}。已有研究大多围绕某一类权限提升问题展开\cite{yang2023take,gu2024epscan,pecka2022privilege}，但不同漏洞的应用上下文、利用前提和影响范围差异较大，所得策略往往只适用于特定场景，跨场景迁移困难。

\noindent\hangindent=1em\hangafter=1 (3) \textbf{漏洞安全响应能力薄弱}。策略编写高度依赖安全专家的个人经验，面对复杂异构的生产环境，难以形成可规模化、可快速响应的工程流程。

\textbf{大语言模型的推理与代码生成能力}为自动化生成防控策略提供了新的可能，但将其应用于漏洞防控场景仍需克服以下研究挑战：

\noindent\hangindent=1em\hangafter=1 (1) \textbf{补丁窗口期内的快速响应}。权限提升漏洞从披露到官方补丁发布之间往往存在较长的空白期。本文对2020至2025年间55个云原生权限提升漏洞样本的统计表明，$30.4\%$ 的漏洞在披露后长时间处于无补丁状态（如图~\ref{fig:patch-window}所示）。补丁的发布、验证与分发本身需要时间，而生产环境的组件依赖复杂、兼容性要求严格，进一步拖延了升级进度。因此补丁在生产环境中就绪前如何快速生成可用的临时防控措施，是需要优先解决的问题。

\noindent\hangindent=1em\hangafter=1 (2) \textbf{多类型漏洞的领域知识融合}。权限提升漏洞涵盖 $\mathrm{RBAC}$ 滥用、容器逃逸、$\mathrm{API}$ 越权等多种攻击类型，各自的成因、利用前提和波及范围差别很大。要让大模型生成有针对性的策略，需要先将分散在代码仓库、漏洞公告、安全社区等渠道中的异构上下文信息加以收集与结构化组织，形成可被检索调用的领域知识体系。

\noindent\hangindent=1em\hangafter=1 (3) \textbf{大模型生成的不确定性控制}。大语言模型在将漏洞语义转化为可执行策略代码时，存在产生幻觉、逻辑矛盾或偏离实际运行环境的风险。如果缺乏有效的验证与校正环节，生成的策略可能无法正确阻断攻击甚至干扰正常业务。

\section{研究内容与成果}
基于上述现实需求，本文聚焦于补丁窗口期内云原生权限提升漏洞的动态防控。按照控制手段的作用方式，可将相关措施概括为监控策略与防护策略两个互补层次。其中，防护策略侧重在漏洞利用发生前阻断关键条件并收敛攻击面；监控策略则侧重运行时异常行为的持续观测与取证。

\begin{figure}[htb]
    \centering
    \includegraphics[width=1\textwidth]{images/总体框架.png}
    \bicaption{基于多智能体的策略化漏洞防控研究总体框架}{Overall multi-agent framework for strategy-based vulnerability prevention and control based on large language models}\label{fig:overall-framework}
\end{figure}

如图~\ref{fig:overall-framework}所示，本文提出的智能防控框架以权限提升类 $\mathrm{CVE}$ 为输入，依托大语言模型（LLM）与多智能体协同，结合检索增强（RAG）、思维链（CoT）与反馈优化（Feedback）等技术，围绕安全知识支撑、策略生成、策略验证及平台工具建设，形成从漏洞披露到输出结构化 JSON 临时防控策略的自动化流程。具体研究内容如下：

\textbf{（1）融合上下文的安全知识库}。面向第三方开源应用场景，从代码仓库、议题（Issue）/合并请求（Pull Request）、$\mathrm{CVE}$ 公告等多源渠道汇聚漏洞证据，并构建权限提升漏洞的分类框架与领域知识库，为策略生成提供结构化证据链。

\textbf{（2）大模型驱动的漏洞防控策略生成}。依托多智能体协同机制，经由证据检索、威胁分析、策略草案生成、评审与迭代修订等阶段，将漏洞攻击链转化为可在 $\mathrm{Kubernetes}$ 平台快速落地的监控与防护策略。

\textbf{（3）策略验证}。对研究方法开展静态评估与动态验证：静态阶段提出多维度多主体交叉评审方法，对防控策略进行静态质量评估；动态阶段在实验环境中进行案例分析，基于漏洞复现与策略部署对策略效果进行动态评估。

\textbf{（4）漏洞安全策略生成与管理平台工具}。开发了涵盖知识库构建、工作流管理、模型对接、人工交互与策略部署的平台化工具，支持本研究方法实践落地。
