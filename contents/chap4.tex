
\chapter{面向云原生权限提升漏洞的智能化防控系统设计与实现}\label{chap:system}

本章讨论第三章提出的方法支持系统的设计与实现，形成覆盖漏洞知识管理、会话驱动生成、专家评审和策略交付的完全系统。下文从需求分析、总体设计和详细设计三个层面展开说明。

\section{需求分析}



系统围绕\textbf{安全工程师}与\textbf{专家评审员}两类角色组织核心用例，见图~\ref{fig:role_use_case}。安全工程师负责选择漏洞实例、发起分析会话、查看证据与候选策略，并完成部署与验证；专家评审员负责对同类型候选策略进行三维质量评审、排序确认与反馈修订。

\begin{figure}[htb]
    \centering
    \includegraphics[width=0.8\textwidth]{images/chap4/role_use_case}
    \bicaption{系统用户角色与核心用例}{System user roles and core .use cases}
    \label{fig:role_use_case}
\end{figure}
结合用例图中角色的职责以及第三章的方法链条，系统需要具备以下五项核心能力：

\noindent\hangindent=2em\hangafter=1 (1) \textbf{知识库管理}：支持导入、检索与维护权限提升相关CVE条目及其关联证据，并自动化抓取相关开源仓库信息并构建向量化数据库，为后续构建安全上下文 $c$ 提供可追溯数据。

\noindent\hangindent=2em\hangafter=1 (2) \textbf{智能体调度}：围绕漏洞实例，通过构建不同智能体进行相关安全知识上下文构建、漏洞分析、安全策略相关代码生成。针对生成的相关代码进行策略性评价并进行迭代优化，最终输出同类型候选策略集合。

\noindent\hangindent=2em\hangafter=1 (3) \textbf{三维质量评审与排序确认}：接收专家评审意见，以降低噪声并提升可部署性。围绕有效性、无干扰性和可部署性对同类型候选进行排序比较，并形成可审计的确认结果。

\noindent\hangindent=2em\hangafter=1 (4) \textbf{策略交付与部署验证}：将通过确认的候选策略下发至目标环境，并记录执行状态、验证结果与审计信息。

\section{总体设计}

系统采用分层架构，自顶向下分为界面层、服务层、智能引擎层和数据层，见图~\ref{fig:system_architecture}。该分层并不是对方法步骤的简单堆叠，而是将第三章中的知识组织、分析生成、评审优化与结果交付拆解为具有明确职责边界的实现单元，使各层可以独立演化、独立测试，同时通过定义清晰的接口契约保持整体一致。

在设计取向上，系统遵循三条核心原则。其一，\textbf{职责分离}：将展示逻辑、业务编排、智能分析与数据持久化分置于不同层次，避免跨层耦合；各层间以 REST 接口和内部函数调用为唯一通信方式，上层不直接访问下层的内部状态。其二，\textbf{会话驱动的迭代生成}：系统以会话为基本单元组织候选策略的生成与优化过程，同一漏洞实例可在多个会话中产出不同版本的候选集合，支持按需追加评审轮次而无须重新触发全量生成。其三，\textbf{全程可审计}：证据来源、中间分析结果、评审意见与排序确认均随候选策略一并持久化，确保每条最终交付结论均可追溯到对应的上下文依据与专家决策记录。

四个层次的职责如下：

\noindent\hangindent=2em\hangafter=1 (1) \textbf{界面层}：基于 Vue3 构建单页应用，采用 Pinia 管理应用级状态，并集成 ECharts 可视化组件，负责 CVE 详情展示、策略交互与评审结果呈现。界面层通过 HTTP 调用服务层接口，不直接访问智能引擎或数据层，所有业务操作均通过接口提交。

\noindent\hangindent=2em\hangafter=1 (2) \textbf{服务层}：采用 Flask 实现 REST API 网关，负责请求路由、访问控制与接口编排；同时通过任务调度器管理耗时较长的会话任务，并协调知识检索、候选策略生成、评审提交与部署验证等流程。耗时任务异步执行，接口以轮询方式反馈进度，避免长连接阻塞。

\noindent\hangindent=2em\hangafter=1 (3) \textbf{智能引擎层}：封装系统核心分析能力，由 KPEAgent 引擎统一调度安全知识整理、漏洞分析、候选策略生成、评审反馈吸收与策略优化等处理单元，完成从漏洞实例到候选策略集合 $\Pi_v$ 的迭代生成。该层对服务层暴露统一的调用入口，屏蔽模型切换、提示词组装与重试控制等实现细节。

\noindent\hangindent=2em\hangafter=1 (4) \textbf{数据层}：负责数据持久化与检索支撑，包括存放 CVE 元数据、证据片段、中间分析结果与候选策略对象的文件存储，以及支持安全上下文构建的向量索引库。向量索引按漏洞实例独立维护，保证多实例并发检索互不干扰。

\section{详细设计}
\subsection{数据模型设计}

系统持久化围绕四类核心实体展开（图~\ref{fig:storage_schema}），分别对应第三章中的漏洞实例 $v$、分析会话、候选策略集合 $\Pi_v$ 与评审结果：\textbf{CVE 实体}以 \texttt{status} 枚举字段驱动处置状态机，与会话呈一对多关系；\textbf{会话实体}记录模型配置与提示词模板，承载从证据检索到策略生成的完整上下文；\textbf{策略实体}保存生成内容、推理链快照与 RAG 召回片段，支持来源追溯与版本对比；\textbf{排序实体}存储评审员标识、时间戳与多维评分，关联会话与策略，记录专家决策的即时快照。

\subsection{详细流程设计}

图~\ref{fig:cve_lifecycle} 以程序流程图描述 CVE 处置总体流程，包含六个顶层状态。\textbf{未处理}为初始态，漏洞条目导入后安全工程师确认范围并触发分析。\textbf{策略生成与优化中}对应第三章 \ref{subsec:kb}～\ref{subsec:agent} 节的核心方法链：五个智能体依序完成证据召回、漏洞分析、候选生成、评审与优化，形成 $\text{RAG}\to\text{CoT}\to\text{Feedback}$ 迭代闭环，输出候选策略集合 $\Pi_v$；$\Pi_v$ 中存在满足质量阈值的候选或累计轮次达到上限时，自动推进至\textbf{待评审}状态。\textbf{待评审}阶段专家对候选进行三维排序（对应第三章 \ref{subsec:quality} 节），质量不足时驳回并附注意见，流程回退重新迭代。\textbf{已批准}后排序结果、评审者标识与评分快照写入持久层。\textbf{部署中}将 $\pi^{\star}$ 推送至目标集群并执行配置合规验证，验证失败回退至已批准状态，由工程师确认后重新部署。\textbf{已部署}为终止态，处置证据链完整闭合。

\subsection{交互时序设计}

候选策略生成涉及证据检索、结构化分析、候选组织与反馈修订等多轮处理，单次任务耗时较长，因此系统采用异步交互时序。完整链路分为四个阶段，前两个阶段见图~\ref{fig:pipeline_sequence_a}，后两个阶段见图~\ref{fig:pipeline_sequence_b}。

\textbf{阶段一：会话创建。}安全工程师选定目标 CVE 后提交创建请求，服务层在数据持久层初始化会话目录结构并返回 \texttt{session\_id}，后续所有操作均绑定至该会话上下文。

\textbf{阶段二：安全上下文构建与候选策略生成。}工程师发起生成请求后，服务层以异步任务形式启动智能体引擎管线：引擎依次完成证据检索、安全上下文 $c$ 构建、漏洞分析、候选策略生成与评审优化，将中间分析结果与候选策略集合 $\Pi_v$ 同步写入持久层，任务完成后经轮询接口将结果返回前端。
\begin{figure}[htb]
    \centering
    \includegraphics[width=0.8\textwidth]{images/chap4/pipeline_sequence_a}
    \bicaption{会话创建与候选策略生成时序（UML 时序图）}{Session creation and candidate strategy generation sequence (UML)}
    \label{fig:pipeline_sequence_a}
\end{figure}
\textbf{阶段三：评审反馈驱动优化。}专家评审员提交修改意见后，服务层携带反馈内容重新调用智能体引擎，策略优化智能体据此修订 $\Pi_v$ 并将更新版本写入持久层。该阶段可按需触发多次，每次修订均以独立记录追加存储，原始版本不被覆盖。

\textbf{阶段四：质量排序与结果确认。}专家完成拖拽排序并填写三维评分后提交确认请求，服务层首先执行同类型候选的全序完整性校验，通过后将排序结果、维度评分与评审员标识一并写入持久层，CVE 处置状态随即迁移至"已批准"。

    \bicaption{评审反馈优化与质量排序确认时序（UML 时序图）}{Review feedback optimization and quality ranking confirmation sequence (UML)}

\section{系统展示与验证}

本节按功能模块说明系统的交互流程与实现方式,并验证系统功能。下文依次介绍知识库管理、策略生成与优化、专家评审与排序以及策略部署管理四个模块。

\subsection{CVE 知识库管理}

知识库管理模块承担漏洞条目的汇聚、检索、证据关联与状态维护，是安全上下文构建的入口环节。该模块对应服务层的 CVE 知识库组件，直接影响 CVE 实体的 \texttt{status} 字段及后续会话流程。如图~\ref{fig:ui_cve_list} 所示，系统主界面以列表视图展示已录入的 CVE 条目，核心字段包括 CVE 编号、漏洞摘要、CVSS 风险评分和当前处置状态。界面上方提供关键词检索与状态筛选功能，支持安全工程师依据漏洞编号、漏洞类型或关键描述快速定位目标记录；选择具体条目后，系统即可进入详情视图并发起分析会话，为后续候选证据检索和安全上下文整理提供统一入口。

\subsection{策略生成与优化}

策略生成与优化模块负责将漏洞证据转化为可交付的候选策略，并通过评审反馈闭环持续修订结果。系统以会话为基本单元，依次经过证据检索、结构化分析与候选生成三个阶段。证据检索阶段（图~\ref{fig:ui_rag}）从漏洞实例抽取语义特征，在知识库中召回 Top-K 相关片段，界面同时展示来源文档与相关度得分供人工核验。结构化漏洞分析阶段（图~\ref{fig:ui_cot}）展示攻击路径分解、权限边界识别与 Kubernetes 控制点映射等中间步骤，便于复核。完成分析后系统输出候选策略集合，专家评审意见可驱动再生成，界面并列展示原始版本与修订版本并高亮变更位置。

\subsection{专家评审与排序}

专家评审与排序模块通过”定性评审 + 拖拽排序”两阶段引入专家知识。评审阶段收集围绕有效性、干扰风险与前置条件的逐项反馈，驱动策略优化。排序阶段如图~\ref{fig:ui_ranking} 所示，专家对同类型候选进行拖拽排序并填写三维维度评分；系统提交前执行全序完整性校验，确认后将排序结果、维度评分与评审员标识写入持久层，形成可审计的偏好数据集。
