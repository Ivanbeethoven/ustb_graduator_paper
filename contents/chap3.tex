
\chapter{云原生权限提升漏洞智能化安全策略生成方法}\label{chap:method}


本章阐述面向云原生权限提升漏洞智能化安全策略生成方法，介绍研究动机、方法框架，并给出一个方法示例。

\section{研究动机}

云原生应用运行涉及关键资源控制，权限提升攻击会造成严重集群化失控危害。云原生应用与控制节点、工作负载、网络插件等组件进行数据交互，权限提升漏洞一旦被利用，攻击者可能从单个组件的异常行为扩展到集群资源访问和恶意控制。面向云原生权限提升漏洞的防控需要解决以下问题：

\noindent\hangindent=2em\hangafter=1 (1)\textbf{临时防控措施及时性}。权限提升漏洞公开后，系统方需要在有限时间内判断受影响的应用组件和防控措施。即使上游已经给出修复补丁，生产集群在修复前需要完成依赖检查和变更审批等流程。因而，漏洞处置需在补丁部署前生成临时策略，对特定权限提升漏洞相关的高风险操作或关键攻击路径进行约束。

\noindent\hangindent=2em\hangafter=1 (2)\textbf{现有方法有效性不足}。配置扫描\cite{shamim2025prescription,k8smanifests2023}偏重静态风险扫描，与漏洞相关性不足；运行时监控\cite{falco2025}、准入控制\cite{opa2025,kyverno2025}和网络隔离\cite{Minna_2021,Budigiri_2021}则依赖预先定义的规则或策略。这些机制提供了安全方案，但从漏洞公告到可执行规则之间仍完全依赖人工完成，受到安全经验差异的限制。

\noindent\hangindent=2em\hangafter=1 (3)\textbf{漏洞防控依赖安全知识}。权限提升漏洞形成与 RBAC 授权关系\cite{ferraiolo1995role}、过度授权\cite{yang2023take}、风险组件劫持和敏感信息泄露\cite{kubeguard_icws2025}等多种问题相关，防控安全策略编写需要根据具体漏洞描述以及应用相关的信息推断攻击前提、权限变化路径和可控制点。

针对上述问题，本文提出一种面向云原生权限提升漏洞的智能化安全策略生成方法KPEDefense。该方法通过安全知识库组织多源漏洞证据，形成可追溯的安全上下文；以该上下文作为输入，通过多智能体协同流程完成漏洞分析、策略生成与反馈优化，将权限提升相关知识转化为规则化安全工具可执行的策略；并从有效性、无干扰性和可部署性三个维度对候选策略进行评价与筛选，从而为补丁部署前的漏洞处置提供临时性防控支持。

\section{方法框架}
面向云原生权限提升漏洞的智能化安全策略生成方法KPEDefense由安全知识库、基于多智能体的策略生成与优化、策略代码质量评估三个部分构成，如图~\ref{fig:overall-framework}所示。该方法以权限提升类 CVE 为输入，最终生成针对权限提升漏洞的防护与监控安全策略。总体流程如下：

(1)\textbf{云原生安全知识库构建}：从第三方开源应用代码仓库的多源信息中采集上下文特征，形成包含 CVE/CWE 统计、权限提升风险分类框架与向量化领域知识的安全知识库，为后续分析提供可检索的证据支撑；

(2)\textbf{基于多智能体的策略生成与优化}：以权限提升 CVE 为输入，通过安全知识检索上下文构建、思维链推理与反馈优化等多智能体协同工作流生成安全策略候选集合；

(3)\textbf{策略代码质量评估}：采用多源大模型排名进行静态评估，给出安全策略代码质量的量化评分，此外在实验中通过案例分析和动态评测方式进行动态评估。

\subsection{基本概念定义}\label{subsec:def}

以下将核心对象形式化为漏洞实例、安全上下文与安全策略三类实体。
\begin{flatdefinition}{漏洞实例}\label{def:vuln-instance}
设 $\mathcal{V}$ 为漏洞实例空间，任一漏洞实例表示为
\begin{equation}
v=\langle \mathit{id},\,d,\,m \rangle\in\mathcal{V}
\end{equation}
其中 $\mathit{id}$ 为漏洞 CVE 编号，$d$ 为漏洞描述文本，$m$ 为元数据，记录严重性、受影响组件及版本范围等属性。
\end{flatdefinition}

\begin{flatdefinition}{安全上下文}\label{def:security-context}
给定漏洞实例 $v$，其安全上下文 $c$ 为带来源标识的有限证据集合：
\begin{equation}
c = \bigl\{\,\langle t_i,\,\mathit{src}_i \rangle \mid i\in[n_c] \,\bigr\}
\end{equation}
其中 $t_i$ 为证据内容，$\mathit{src}_i$ 为来源标识(如文档路径、公告链接或代码位置)，用于支撑策略生成中的证据追溯与复核，$[n_c]=\{1,2,\ldots,n_c\}$ 为证据索引集合，$n_c$ 为检索到的证据数量。
\end{flatdefinition}

\begin{flatdefinition}{防控条目}\label{def:control-item}
安全策略的基本组成单元为三元组
\begin{equation}
e = \langle \tau,\;m,\;\mathbf{a} \rangle
\end{equation}
其中 $\tau\in\{\mathrm{mon},\mathrm{prot}\}$ 为控制类型：监控型策略($\mathrm{mon}$)持续观测运行时状态并触发异常告警；防护型策略($\mathrm{prot}$)主动阻断权限滥用并收缩攻击面。$m$ 为控制机理，描述该措施的作用路径，如 Falco 规则告警、Kyverno 准入审计或 RBAC 权限收缩。$\mathbf{a}=(a_{m_1},\ldots,a_{m_k})$ 为 $m$ 对应的执行表达序列(规则片段、配置声明或可执行命令)，每个 $a_{m_i}$ 对应 $m$ 的一个可部署策略代码。
\end{flatdefinition}

\begin{flatdefinition}{安全策略}\label{def:security-strategy}
针对漏洞实例 $v$ 的安全策略为防控条目的有限集合
\begin{equation}
\pi = \{e_1,\;e_2,\;\ldots,\;e_n\}
\end{equation}
其中每个 $e_i=\langle \tau_i,\;m_i,\;\mathbf{a}_i\rangle$ 为定义~\ref{def:control-item} 所述防控条目。多条目策略将防护型与监控型措施协同组织，弥补单一类型在阻断能力或持续观测方面的局限。
\end{flatdefinition}

\begin{flatdefinition}{生成配置}\label{def:gen-config}
设 $\mathcal{A}$ 为方法配置集合，$\mathcal{M}$ 为大语言模型集合，任一生成配置实例记为 $g=(a,h)\in\mathcal{A}\times\mathcal{M}$，表示方法配置 $a$ 与底层模型 $h$ 的组合。
\end{flatdefinition}

\begin{flatdefinition}{候选策略集合}\label{def:candidate-strategy-set}
围绕漏洞实例 $v$ 的候选策略集合记为
\begin{equation}
\Pi_v=\bigcup_{g\in\mathcal{G}_v}\Pi_v^{(g)}
\end{equation}
其中 $\mathcal{G}_v\subseteq\mathcal{A}\times\mathcal{M}$ 为 $v$ 采用的生成配置集合(定义~\ref{def:gen-config})，$\Pi_v^{(g)}\subseteq\Pi$ 为配置 $g$ 输出的候选子集，$\mathcal{E}$ 为防控条目全集，$\Pi=2^{\mathcal{E}}$ 为安全策略全集。$\mathcal{A}$ 与 $\mathcal{M}$ 的具体取值在第五章实验部分给出。
\end{flatdefinition}

\subsubsection{(1)数据采集}

以 K8s 及其生态开源应用为研究对象，首先从 CNCF Landscape 获取云原生应用清单，将清单条目名称映射到其官方代码仓库，形成后续漏洞检索与证据收集的目标集合。使用 NIST NVD\footnote{NIST NVD(National Vulnerability Database)：\url{https://nvd.nist.gov/}}、MITRE CVE 官方库\footnote{MITRE CVE：\url{https://cve.mitre.org/}}与安全公告平台 GitHub Security Advisory\footnote{GitHub Security Advisory：\url{https://github.com/advisories}}三个来源，围绕权限提升相关关键词对相关开源项目开展多源漏洞检索，获得初步 CVE 候选池。

\subsubsection{(2)漏洞筛选}
为从 CVE 候选池中筛选出高质量样本，研究采用关键词约束、严重性阈值与人工复核相结合的三重过滤策略：
\begin{itemize}
    \item \textbf{关键词约束}：在 CVE 描述与参考链接中匹配 Privilege Escalation、Authorization Bypass、Improper Access Control、RBAC、ServiceAccount、ClusterRole、Container Escape/Sandbox Escape/Breakout 等关键词；
    \item \textbf{严重性阈值}：采用 CVSS v3.x 评分，并以 $\geq 5.0$ 的中危及以上漏洞为主要对象；
    \item \textbf{人工复核}：对候选条目结合公告原文、厂商通告与社区讨论进行复核，剔除重复或与权限提升无关的记录，并补全攻击前提、影响面与可用缓解信息。
\end{itemize}


\subsubsection{(3)漏洞分类}

漏洞样本的分类方式影响后续策略生成方向。为此，研究构建了面向策略生成场景的两级成因分类框架，旨在为模型提供稳定且可解释的风险语义线索，同时提示安全工具类型的使用。

为建立该分类框架，首先参考现有权限提升漏洞 CVE 采用的弱点分类体系 CWE(Common Weakness Enumeration)。CWE 是 MITRE 维护的软件弱点枚举体系，可用于将具体 CVE 归并到更抽象的弱点类型。CWE 体系并不是严格互斥的分类框架。同一漏洞往往会同时对应多个弱点条目，不同条目在抽象层次上也可能彼此交叉。在收集的 55 个权限提升漏洞中，有 20 个样本同时关联两个及以上 CWE 标签，占比 36\%。为更客观地反映 CWE 分布，统计时令每个 CVE 的总权重为 1，多标签样本按标签数平均分配。
\begin{figure}[htb]

    \includegraphics[width=0.9\textwidth]{images/cwe_distribution_pie.png}

综上，权限提升漏洞可能存在多种特性，而 CWE 的类目划分并不能指出权限提升漏洞攻击的关键攻击路径。为此，构建面向云原生权限提升漏洞的两级成因分类框架。该框架基于漏洞的关键成因，其中一级分类用于概括高层风险来源，如安全逻辑缺陷、配置缺陷、代码注入和敏感信息泄露；二级分类则进一步细化到更贴近防控动作选择的类型，如授权验证不完善、默认不安全配置等。在策略生成阶段，分类结果作为提示词中的结构化约束，引导模型先识别漏洞的主要成因，再定位关键控制点，最后组织可执行的防控动作，从而减少无关信息并提高策略的有效性。完整的分类见表\ref{tab:cloud-native-vuln}。

以下对各级分类分别展开说明。

\textbf{1)配置缺陷}指应用或基础设施的配置不当导致的安全漏洞，主要包括两种情形：
\begin{enumerate}[label=\textcircled{\small\arabic*},leftmargin=*]
    \item 冗余权限：K8s RBAC 配置不当、Role/ClusterRole 规则范围过宽或绑定关系不合理等，使低权限主体获得超出其职责的资源访问与高危操作能力。云原生应用在安装时申请了远超其功能需求的集群级权限，一旦被攻击者利用，即可借助已有 ServiceAccount 绑定关系直接接管集群关键资源\cite{o1995redundant,yang2023take}。
    \item 网络隔离不足：容器、Pod 或服务间缺乏必要的网络隔离策略，导致攻击者在突破单一组件后可借助集群内部网络横向移动。
\end{enumerate}

\textbf{2)安全逻辑缺陷}指应用代码中的安全机制设计或实现不当，涵盖以下情形：
\begin{enumerate}[label=\textcircled{\small\arabic*},leftmargin=*]
    \item 访问控制缺陷：应用的权限检查逻辑存在遗漏或条件判断不完整，允许攻击者通过构造特定请求绕过鉴权层，直接操作受保护资源；
    \item 身份验证绕过：认证机制在特定调用路径下存在设计缺陷，攻击者可伪造令牌、利用过期凭证或跳过认证前置步骤，以合法身份的名义执行未授权操作；
    \item 输入验证不足：对请求参数、资源标识或边界条件的校验不充分，导致攻击者借由畸形输入触发意料之外的执行分支，进而扩大权限边界或绕过越权检查路径；
    \item 授权验证不完善：权限检查仅覆盖主流程，在某些操作路径、回调分支或边界条件下存在验证缺失，使攻击者得以通过非常规路径访问需要更高权限的功能。
\end{enumerate}

\textbf{3)敏感信息泄露}指重要的身份凭证、密钥或访问令牌在不应暴露的位置意外出现，攻击者可借此直接获取高权限访问能力，常见形式包括：
\begin{enumerate}[label=\textcircled{\small\arabic*},leftmargin=*]
    \item API 端口暴露：管理接口、内部 API 或调试端口未设访问控制地暴露在集群网络中，攻击者可直接调用高权限接口执行敏感操作；
    \item 日志泄露：应用错误处理不当，将包含密钥、访问令牌或命令历史的原始信息写入日志，使具有日志读取权限的攻击者得以提取有效凭证；
    \item 配置文件泄露：部署清单或环境变量中存在硬编码的凭证或密钥，一旦配置文件被读取即可直接复用高权限账户。
\end{enumerate}

\textbf{4)代码注入}指应用对外部输入的处理不当，使攻击者得以将恶意指令混入正常执行流，从而在目标系统上以当前进程权限执行任意操作。典型子类包括：
\begin{enumerate}[label=\textcircled{\small\arabic*},leftmargin=*]
    \item 命令注入：应用将用户可控内容拼接进系统调用或 shell 命令，攻击者通过注入分隔符或控制字符劫持执行流，以容器或宿主机进程权限运行任意命令；
    \item 路径遍历：应用在拼接文件路径时未做规范化处理，攻击者借助 \texttt{../} 序列突破预设目录边界，读取或写入系统敏感文件，进而获取凭证或修改关键配置。
\end{enumerate}

\subsubsection{(4)知识库构建}

知识库构建阶段的目标是将与漏洞 $v$ 相关的多源材料组织为带来源标注的证据集合，并建立支持按需取证的检索增强生成。围绕 $v$ 构建知识库 $\mathcal{K}_v$ 后，策略生成阶段即可通过语义检索提取相关证据片段，并按需组装为安全上下文 $c$，为后续分析提供可追溯的事实依据。


安全知识库基于开源仓库内多源信息构建分层向量数据库。首先自动化抓取每个漏洞关联的开源应用仓库，收集代码与文档，以及与漏洞相关的安全公告、议题(Issue)/合并请求(Pull Request)讨论和修复提交信息。在完成材料收集后，研究对不同材料采用差异化分块策略以兼顾证据粒度与可复核性：对代码和配置按行切分，同时对文档则按段落与窗口切分，并保留适当重叠以减少跨块语义断裂。为实现语义层面的证据召回，研究为每个文本块构造向量表示，并建立近邻检索索引。具体采用 sentence-transformers 框架中的 MPNet 句子编码器 all-mpnet-base-v2 完成文本表示\cite{reimers2019sentencebert,song2020mpnet}，并基于 FAISS\cite{douze2024faiss} 构建相似度索引。为保证可追溯性与可复现性，索引与元数据同步持久化，内容包括向量索引文件、块级元数据以及构建配置。

上述流程得到的向量知识库为后续策略生成提供了可追溯的证据支撑：模型分析漏洞和对应防控手段时可检索相关事实与上下文片段，并通过来源标识完成定位与复核。


\subsection{基于多智能体的安全策略生成与优化}\label{subsec:agent}


策略生成阶段以漏洞实例 $v=\langle \mathit{id},d,m\rangle$ 与安全上下文 $c$ 为输入，在不同生成配置 $g=(a,h)$ 下开展多次独立生成，并将各配置输出的安全策略子集按定义~\ref{def:candidate-strategy-set} 汇合为候选策略集合 $\Pi_v$。完整工作流如图~\ref{fig:method}所示，分为安全上下文构建、基于漏洞分析思维链的策略生成、基于评审反馈的策略优化三个步骤，分别简写为 $\text{RAG}$、$\text{CoT}$ 和 $\text{Feedback}$。其中，安全上下文构建负责将知识库证据组织为定义~\ref{def:security-context} 所述的 $c$；策略生成负责将漏洞分析结果映射为定义~\ref{def:security-strategy} 所述的安全策略 $\pi$；反馈优化则在不改变策略对象基本结构的前提下，对 $\pi$ 中防控条目的控制类型、控制机理与执行表达进行修订，从而形成更适合进入质量评估阶段的候选策略。

\subsubsection{(1)安全上下文构建}

安全上下文构建基于检索增强生成技术(RAG)\cite{lewis2020retrieval}，从上一节构建的云原生安全知识库中检索与漏洞实例 $v$ 相关的证据片段，并将其组织为面向漏洞分析的安全上下文 $c$。检索增强生成将代码、文档、安全公告与修复讨论等多源材料构建为密集向量索引，即本文中的向量化安全知识库，从而在生成前引入与具体漏洞相关的外部证据。与直接将检索结果拼接给模型不同，本文设置安全知识智能体对候选证据进行去重、归并和来源保留，使输出满足定义~\ref{def:security-context} 中 $c=\{\langle t_i,\mathit{src}_i\rangle\mid i\in[n_c]\}$ 的形式。

\subsubsection{(2)基于漏洞分析思维链的策略生成}

基于漏洞分析思维链的策略生成由漏洞分析智能体与策略生成智能体串联完成。漏洞分析智能体以漏洞实例 $v$ 和安全上下文 $c$ 为输入，首先从定义~\ref{def:vuln-instance} 中的漏洞描述 $d$ 与元数据 $m$ 提取受影响组件、版本范围和风险等级，再结合 $c$ 中带来源标识的证据识别触发条件、攻击入口、权限变化路径、影响资源和可控制点，最终形成覆盖漏洞类型、攻击路径、影响范围与成因分类的结构化分析结果。成因分类直接引用第 \ref{subsec:kb} 节的两级框架，其作用在于提示后续防控工具的选择：一级类确定风险来源，二级类进一步锁定对应的控制手段，从而将泛化建议约束为与漏洞语义一致的具体措施。例如，配置缺陷类漏洞优先考虑 RBAC 最小权限、准入控制和网络隔离；代码注入类漏洞优先考虑运行时监控、输入约束与执行边界收缩；敏感信息泄露类漏洞则优先围绕资源读取权限、Secret 管理与异常访问审计生成防控动作。

策略生成智能体在上述分析约束下选择具体实施路径，并将防控动作映射为定义~\ref{def:control-item} 与定义~\ref{def:security-strategy} 所述的策略对象。具体而言，图~\ref{fig:method} 中的监控策略对应 $\tau=\mathrm{mon}$ 的防控条目，用于在运行时发现可疑行为并输出告警；防护策略对应 $\tau=\mathrm{prot}$ 的防控条目，用于通过准入拒绝、权限收缩或网络隔离等方式阻断攻击路径。控制机理 $m$ 表示策略采用的安全工具或作用路径，如 Falco 运行时规则、Kyverno 准入策略、OPA Gatekeeper 约束、NetworkPolicy 或 RBAC 角色调整；执行表达 $\mathbf{a}$ 则保存与 $m$ 对应的 YAML、Rego、Falco 规则或命令序列。由此，每个候选策略 $\pi=\{e_1,e_2,\ldots,e_n\}$ 均可被解释为围绕同一漏洞实例组织的多条防控条目集合，而非若干松散的安全建议。

在生成配置 $g=(a,h)$ 下，策略生成智能体输出当前配置对应的候选子集 $\Pi_v^{(g)}$。不同方法配置 $a$ 和底层模型 $h$ 会带来差异化的推理路径与策略表达，多个候选子集最终合并为 $\Pi_v$，供后续质量评估比较。为保证候选之间具有可比性，生成阶段要求每个 $\pi$ 至少包含防控目标、适用前提、策略代码、验证方式和回滚边界；当安全上下文中证据不足时，模型必须显式保留假设条件，而不能将假设内容写成确定事实。具体智能体提示词见图~\ref{fig:prompt-vuln-analysis} 和图~\ref{fig:prompt-strategy-gen}。

\subsubsection{(3)基于评审反馈的策略优化}

在候选策略生成之后，流程进入评审与迭代优化环节。该环节的目标不是替代下一节的质量评估，而是在候选进入最终排序前发现明显缺陷并完成可执行性修订。\textbf{策略评审智能体}以漏洞实例 $v$、安全上下文 $c$ 与候选策略集合 $\Pi_v$ 为输入，从有效性、无干扰性与可部署性三个维度给出结构化评审，包括每个候选策略的有效点、潜在误报或业务影响、部署风险、验证要点与缺失信息。评审结论需要指出问题所对应的防控条目 $e_i$，并区分是控制类型 $\tau$ 选择不当、控制机理 $m$ 不适配，还是执行表达 $\mathbf{a}$ 缺少必要字段或验证步骤。

\textbf{策略优化智能体}据此对候选策略进行有边界的修订：对于能够支撑漏洞防控目标的条目，保留其核心控制逻辑并补齐部署参数；对于证据不足、作用范围过宽或与业务运行冲突的条目，进行收缩、替换或删除；对于缺少验证与回滚信息的策略，补充可执行命令和回退条件。优化后的结果仍表示为安全策略 $\pi$ 或候选策略子集 $\Pi_v^{(g)}$ 中的元素，不能改变定义~\ref{def:security-strategy} 所规定的基本结构。由此，反馈优化在图~\ref{fig:method} 中形成从策略评审到策略生成的闭环，使候选策略在进入质量评估前完成一次基于证据和结构约束的自我修正。具体提示词范例见图~\ref{fig:prompt-strategy-review} 和图~\ref{fig:prompt-strategy-optimize}。

\subsection{策略代码质量评估}\label{subsec:quality}

策略代码质量评估具有两方面作用：其一，在候选策略集合中识别质量差异并筛选最优策略；其二，作为评估基准，用于比较不同大语言模型和智能体工作流的生成质量。大语言模型在绝对评分任务中难以形成跨样本一致的内部尺度函数，易受文本长度、表达风格与候选顺序等非语义因素影响，产生系统性偏置~\cite{wu2024scoring,wang2023fair,hwang2025persuasion}；排序任务将评价约化为局部比较，有利于降低尺度漂移与偏置累积，结果与人类评审的一致性通常更高~\cite{velez2025writing,liu2023geval,wang2025trustjudge}。

基于排名的多源模型三维质量评价方法如图\ref{fig:quality-eval}所示。该方法基于大模型作为评审员，通过对候选安全策略的排序获得不同安全策略的三维质量向量(定义\ref{def:quality-vector})。安全策略代码质量三个维度如下：
\begin{enumerate}[label=(\arabic*),leftmargin=*]
    \item \textbf{有效性}：安全策略应能准确检测并有效防御与漏洞相关的权限提升攻击；
    \item \textbf{无干扰性}：策略在运行时可能过度限制功能权限，故应最大限度降低对 K8s 集群其他业务正常运行的干扰；
    \item \textbf{可部署性}：策略代码应能够快速部署至K8s 集群，其中的策略条目${e}$应在保持精简和可行性的前提下确保有效性。
\end{enumerate}
\begin{flatdefinition}{三维质量向量}\label{def:quality-vector}
一个安全策略的质量向量量化为一个三维0至1之间的数值向量，数值越高表明质量越好：
\begin{equation}\label{eq:quality-vec}
q(\pi) = \bigl(E(\pi),\;I(\pi),\;D(\pi)\bigr)
\end{equation}
\end{flatdefinition}

    \centering
    \includegraphics[width=1\textwidth]{images/evalution.png}
    \bicaption{基于排名的多源模型三维质量评价方法}{Ranking-Based Three-Dimensional Quality Evaluation Method Using Multiple Models}
    \label{fig:quality-eval}
\end{figure}

针对漏洞 $v$ 的候选安全策略集合 $\Pi_v$，研究先对其中各策略进行匿名化与随机化处理，再将其输入一个或多个大语言模型，由评审模型分别在有效性、无干扰性和可部署性三个维度上给出严格全序。质量评估智能体的提示词简化示例见图~\ref{fig:prompt-quality-eval}。在获得各模型的维度排序后，可先将单个评审主体给出的秩次映射为 $[0,1]$ 区间上的维度得分，再对所有评审主体取均值，得到策略在三个维度上的共识得分，并据此构成安全策略的三维质量向量 $q(\pi)$。若需要进一步从候选集合中选出单个总体最优策略，则可在三维共识得分的基础上按权重聚合为总体质量函数 $Q(\pi)$，从而同时支持分维比较与总排序。

\begin{flatdefinition}{单维归一化秩得分函数}\label{def:ranking}
设 $\mathcal{H}$ 为评审主体集合，$h\in\mathcal{H}$ 为参与独立评审的大语言模型配置。在维度 $\delta\in\{E,I,D\}$ 上，评审主体 $h$ 对候选集 $\Pi_v$ 给出严格全序，记 $r_{\delta}^{(h)}(\pi)$ 为 $\pi$ 在该排序中的秩(最优获秩 $1$，最劣获秩 $n_v=|\Pi_v|$)，则该安全策略在评价维度 $\delta$ 上的质量向量值为：
\begin{equation}\label{eq:rank-score}
s_{\delta}^{(h)}(\pi)=\frac{n_v-r_{\delta}^{(h)}(\pi)}{n_v-1}\in[0,1]
\end{equation}
当 $n_v=1$ 时，该维度不存在排序比较，本文将唯一候选策略的该维度得分记为 1。
对所有评审主体取均值，得维度 $\delta$ 的共识得分
\begin{equation}\label{eq:consensus-score}
\hat S_{\delta}(\pi)=\frac{1}{|\mathcal{H}|}\sum_{h\in\mathcal{H}}s_{\delta}^{(h)}(\pi)
\end{equation}
三维质量向量各分量由对应维度的共识得分给出，即 $E(\pi)=\hat S_E(\pi)$，$I(\pi)=\hat S_I(\pi)$，$D(\pi)=\hat S_D(\pi)$。按 $\hat S_{\delta}$ 降序排列即得维度 $\delta$ 的共识排序 $\bar R_{\delta}$。
\end{flatdefinition}




\begin{flatdefinition}{总体质量函数}
\label{def:overall-quality}
将三维共识得分加权聚合，得总体质量函数 $Q\colon\Pi_v\to[0,1]$：
\begin{equation}\label{eq:quality-func}
Q(\pi)=\alpha_E\hat S_E(\pi)+\alpha_I\hat S_I(\pi)+\alpha_D\hat S_D(\pi)
\end{equation}
其中 $\alpha_E,\alpha_I,\alpha_D$ 为维度权重，且$\alpha_E+\alpha_I+\alpha_D=1$，可按业务场景配置：应急响应场景可提高 $\alpha_E$，生产稳定性优先场景可提高 $\alpha_I$，默认取 $\alpha_E=0.5,\alpha_I=0.3,\alpha_D=0.2$。按 $Q(\pi)$ 降序排列得总排名 $\bar R$。本文默认在 $\Pi_v$ 上计算总体排名；若按类型筛选，则在 $\Pi_v^{\tau}$ 上计算。
\end{flatdefinition}

在实际应用中，策略筛选并非仅根据单一维度做局部判断，而是以总体质量函数 $Q(\pi)$ 为核心排序依据。对于漏洞实例 $v$ 的候选策略集合 $\Pi_v$，系统首先剔除无法通过格式校验、缺少关键部署字段或与目标集群约束明显冲突的候选策略，得到可参与筛选的策略集合 $\Pi_v^{\mathrm{valid}}$。随后对每个 $\pi\in\Pi_v^{\mathrm{valid}}$ 计算三维共识得分 $\hat S_E(\pi)$、$\hat S_I(\pi)$ 与 $\hat S_D(\pi)$，并依据式~\eqref{eq:quality-func} 得到总体质量 $Q(\pi)$。最终交付策略可表示为
\begin{equation}\label{eq:best-strategy}
\pi^{\star}=\arg\max_{\pi\in\Pi_v^{\mathrm{valid}}} Q(\pi)
\end{equation}
其中 $\pi^{\star}$ 为当前权重配置下的最优安全策略。若实际场景对有效性、业务连续性或部署复杂度存在明确底线要求，还可在求解前引入维度阈值，例如要求 $E(\pi)\geq\theta_E$ 或 $D(\pi)\geq\theta_D$，从而避免总体得分较高但关键维度不可接受的策略被选中。当多个候选策略的 $Q(\pi)$ 差异较小时，系统保留排名靠前的若干策略供安全工程师复核，并优先选择具有更清晰证据来源、更小业务影响和更完整回滚方案的策略。通过上述过程，三维质量评价结果被转化为面向部署决策的筛选规则，使 KPEDefense 能够在候选策略集合中选择最符合当前防控目标的安全策略。

\section{方法示例}

Calico 是一套开源的网络和网络安全方案，用于容器、虚拟机、宿主机之间的网络连接。以 Calico CNI 应用中的 \mbox{CVE{-}2024{-}33522} 漏洞为例，进行 KPEDefense 方法示例，分为安全知识库构建、安全策略生成、安全策略评审三个步骤。

\noindent\textbf{(1)安全知识库构建}

在安全知识库构建阶段，首先以 calico 开源仓库中通过爬虫技术抓取代码文件、文档以及Issue，Pull Request等多源信息，入库时保留路径、提交哈希与时间戳等元数据。共计42篇md格式文档和 3476 条 Issue 与 8826 条 Pull Request 讨论记录。

\noindent\textbf{(3)安全策略评审}

多个评审模型在有效性 $E$、无干扰性 $I$、可部署性 $D$ 三维上对 $\Pi_v$ 独立排序，按式~\eqref{eq:consensus-score} 聚合得各策略的三维质量向量 $q(\pi)$，再按式~\eqref{eq:quality-func} 以默认权重($\alpha_E=0.5,\alpha_I=0.3,\alpha_D=0.2$)计算 $Q(\pi)$。综合排名较优的 $\pi_1$，被选为最终交付策略 $\pi^{\star}$。

\section{小结}
本章提出了一种面向云原生权限提升漏洞的智能化防控方法。通过构建多源证据驱动的安全知识库，然后基于多智能体协同机制，将分散信息组织为可检索的安全上下文，并实现从漏洞语义到防控策略的自动化生成与优化；通过基于排序的质量评价方法，对候选策略进行有效筛选和评估。
