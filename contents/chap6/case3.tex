
\subsubsection{漏洞复现}

\noindent\hangindent=2em\hangafter=1 \textbf{漏洞背景}

CubeFS 是面向云原生场景的分布式存储系统，常通过 CSI（Container Storage Interface）插件与 Kubernetes 集成。在 Kubernetes 中，CSI 节点插件通常以 DaemonSet 形式在每个节点上运行（例如 \texttt{cfs-csi-node}），控制器组件以 Deployment 形式运行（例如 \texttt{cfs-csi-controller}）。这类组件需要与 Kubernetes API 交互，但其权限应遵循最小权限原则。

\textbf{CVE 描述}：CVE-2023-30512 的核心问题是 CubeFS CSI 插件的服务账号（如 \texttt{cfs-csi-service-account}）被绑定到了包含\textbf{过度权限}的集群级角色（\texttt{ClusterRole}），从而具备对集群范围 \texttt{Secret} 的读取能力（如 \texttt{get/list}）。一旦攻击者在某节点获得对 CSI 节点插件 Pod 的控制，例如通过节点被入侵、容器逃逸或对系统命名空间特权工作负载的执行能力，便可能滥用该服务账号的权限边界，读取全局敏感信息并进一步演化为集群级权限提升。

\textbf{主要成因分类}：配置缺陷 / 过度授权（Over-privileged RBAC）。

\textbf{攻击链条描述}：攻击链可概括为系统组件身份被过度授权，且在被攻陷后可枚举集群秘密：
\begin{enumerate}
	\item \textbf{身份前置阶段}：CSI 组件使用默认或被误配置的 ServiceAccount 运行；
	\item \textbf{权限放大阶段}：ServiceAccount 被绑定到含 \texttt{secrets} 读取能力的 ClusterRole；
	\item \textbf{控制获取阶段}：攻击者控制某节点上的 CSI Pod（例如 \texttt{cfs-csi-node}）并获得其运行时上下文；
	\item \textbf{数据获取阶段}：攻击者以该 ServiceAccount 身份读取集群 Secret，从而获取高价值凭据（管理员 Token、云凭据等），实现从节点或 Pod 控制向集群控制的升级。
\end{enumerate}

\noindent\hangindent=2em\hangafter=1 \textbf{漏洞复现}

实验在 Kubernetes 测试集群中部署受影响版本的 CubeFS CSI，明确节点插件与控制器组件使用的 \texttt{cfs-csi-service-account}，并导出其对应的 ClusterRole 与 ClusterRoleBinding。权限证据显示，该服务账号关联的 ClusterRole 含有 \texttt{secrets} 资源的 \texttt{get/list/watch} 动词，完整命令与策略清单见附录\ref{app:cve-2023-30512}。

以 \texttt{cfs-csi-service-account} 身份执行 \texttt{kubectl auth can-i list secrets --all-namespaces}，结果返回 \texttt{yes}，表明该账号具备跨命名空间读取 \texttt{Secret} 的能力。攻击者一旦控制 CSI Pod 运行时上下文，即可沿该权限路径继续获取高价值凭据。

\subsubsection{安全策略生成}

KPEDefense 针对该漏洞筛选出的最优策略以 RBAC 最小化与准入防回归为核心：移除 CSI ServiceAccount 对集群范围 \texttt{Secret} 的读取权限，并通过准入规则阻断包含高危动词的 ClusterRole 变更，防止过度授权在修复后重新引入。详细配置见附录\ref{app:cve-2023-30512}。

\subsubsection{安全策略验证}

将最优策略集合部署至实验集群后，重新以 \texttt{cfs-csi-service-account} 身份执行漏洞复现中的权限验证，对有效性、无干扰性与可部署性三个维度逐项验证。

\noindent\textbf{有效性：}
RBAC 收敛后，\texttt{kubectl auth can-i list secrets --all-namespaces} 的结果由 \texttt{yes} 变为 \texttt{no}，说明 CSI ServiceAccount 对 \texttt{Secret} 的跨命名空间读取能力已移除。准入规则生效后，包含 \texttt{secrets} 读取动词的 ClusterRole 变更无法再次进入集群，过度授权回归路径被阻断。

\noindent\textbf{无干扰性：}
策略收紧对象限于 CSI 组件的非必要权限，PVC/PV 生命周期、挂载与卸载流程保持正常。准入规则先以审计模式运行，确认无平台必需权限被误拦截后再切换至强制模式。

\noindent\textbf{可部署性：}
RBAC 规则与准入策略均采用 YAML 形式管理，可直接纳入 Git 基线并通过 \texttt{kubectl apply} 部署。该方案依赖 Kubernetes 原生权限机制与常用准入组件，适合在多集群场景中复用。

就 CVE-2023-30512 而言，KPEDefense 筛选的最优策略组合在三维验证中通过。CSI ServiceAccount 的 \texttt{Secret} 读取能力被移除后，节点或 Pod 被攻陷后继续触达集群敏感凭据的路径被阻断。该方案可作为版本修复前的补充缓解措施，最终仍需结合官方修复与安装清单更新完成根因处理。
